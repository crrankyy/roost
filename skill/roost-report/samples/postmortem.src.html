Incident postmortem · BUG-0005 · critical

The screen-reader adapter attached after AppKit had observed the window, and zmd crashed

zmd's release and debug builds died with SIGSEGV minutes after launch on the lead's Touch Bar Mac. The bug was recorded on 19 October, fixed on 20 October in one 20-minute session, and two follow-ups are still open.

Key findings
  1. The crash came from attach order, not a timer. The accesskit adapter subclassed a view AppKit's Touch Bar finder had already KVO-swizzled; see Cause.
  2. The risk was written down two days earlier. Q-0002 named it and the fix; a passing VoiceOver check led F-003 to record that attaching late was fine; see Cause.
  3. The fix is small and was checked by A/B. The window now opens hidden and is shown after the adapter attaches; see Fix.
  4. The record holds no user impact. Only the lead's machine is named, and no build was public until 24 October; see Impact.
  5. Two follow-ups are open. The lead's release-build check has no record, and the architecture doc still says to attach after the window is visible; see Remediation.

Cause

AppKit observed the view before the adapter subclassed it

The resolving status note and the fix commit give the mechanism. The record keeps no backtrace, core dump or log of the investigation itself; these two texts are all there is.

BUG-0005 status note · agent · 2026-10-20T14:03:48ZRoot cause: the accesskit SubclassingAdapter attached after AppKit's Touch Bar finder had KVO-swizzled WinitView (the adapter requires attaching before the view is shown or focused); KVO then jumped through a null cached observationInfo pointer when the finder invalidated its observations on an app switch.
  1. iced shows the window

    zmd launched with .window_size(WINDOW_SIZE), so the window was visible from its first frame.

  2. AppKit observes the view

    "When the window became key before the editor existed AppKit had already KVO-swizzled WinitView."

  3. The adapter subclasses the wrong class

    Attached once the editor existed, the adapter "subclassed NSKVONotifying_WinitView" instead of the plain view.

  4. An app switch tears down the observers

    "KVO then jumped through a null cached observationInfo pointer the next time the finder invalidated its observations, typically when the user switched apps."

Source: commit f4a3ae0 message, quoted; step 1 from its diff.

The risk was known and judged safe on a passing check

Nobody skipped a step. The spike asked the right question, the lead ran the check, and VoiceOver worked, so the early warning read as answered. The check could not show a crash that needs a Touch Bar observer and an app switch.

Q-0002 context · 18 Oct 21:52ZOne known risk: accesskit_macos documents that SubclassingAdapter should be created before the view is first shown, and iced only hands out the window after it is visible; if VoiceOver ignores the window, that is the likely cause and the fix (open hidden, install, show) is small.
F-003 as-built · facts for Phase 2 · commit 51c7c35the adapter can be installed after iced shows the window (accesskit's docs prefer before; VoiceOver still picked it up)
Gap

The record never explains the 139 s in the bug's title. The fix commit says the crash came "a few minutes after launch" and "typically when the user switched apps", which suggests 139 s was when the lead switched apps, not a timer. That is a reading of the record, not a finding in it.

Fix

The window now opens hidden and is shown after the adapter attaches

One file, 23 lines added and 7 removed, in crates/zmd-app/src/app.rs. This is the order Q-0002 had proposed.
